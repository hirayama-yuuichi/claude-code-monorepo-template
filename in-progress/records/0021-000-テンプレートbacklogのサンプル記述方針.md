# 設計判断ログ

## 0021-000: テンプレートbacklogのサンプル記述方針

- 日付: 2026-05-10
- 状態: 採用
- ドキュメント: 完了
- 実装: 完了

### 背景

rec-0017-010 の V2 対応でテンプレートの backlog.md からサンプル記述を削除したが、空のままでは初めて使うユーザーが書き方を把握できない。

### 判断

テンプレートの `in-progress/backlog.md` にはサンプル記述を残す。構成は以下の3セクション：

```
## 次回作業

（人が記入）

## 作業予定

- [rec-0001](./records/0001-sampleタイトル.md): タスク説明
- sampleタスク2
- sampleタスク3

## YYYY/MM/DD
- 済 [rec-0001](./records/0001-sampleタイトル.md): タスク説明
- 済 sampleタスク1
- 済 sampleタスク2
```

### 理由

- サンプルがあることで、初めて使うユーザーが書き方・運用フローを即座に理解できる
- records のサンプル（`0000-000-sample.md`）と同様、サンプルは残す方針に統一する
- 空にしてしまうと「次回作業・作業予定・YYYY/MM/DD」の3セクション構成の意味が伝わらない

### 却下した選択肢

| 案 | 却下理由 |
|---|---|
| サンプル記述を削除して空にする | 初めて使うユーザーが書き方を知る手がかりがなくなる |

### 影響

- テンプレートの backlog.md にサンプル記述が残る
- 新規プロジェクト導入時、不要なサンプル行は手動で削除する運用になる

### docs 記載方針

- 対応済み（backlog.md 自体がドキュメントを兼ねる）

### 実装方針

- 対応済み（`packages/template/in-progress/backlog.md` を更新）
