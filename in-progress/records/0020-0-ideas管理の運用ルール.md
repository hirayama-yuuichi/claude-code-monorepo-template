# 設計判断ログ

## 0020: ideas.md の運用ルール

- 日付: 2026-05-09
- 状態: 提案
- ドキュメント: 未着手
- 実装: 未着手

### 背景

`in-progress/ideas.md` にアイデアを書き溜める運用をしているが、以下の問題が出てきた：

- 思いついた順に追記するだけで整理されない
- いつのアイデアか分からなくなる
- records に昇格したものが ideas.md に残り続ける

### 判断

以下のルールで ideas.md を運用する：

1. **追記は最上部に**（新しいものが上）
2. **日付を必ず記録する**（`- YYYY-MM-DD: アイデア内容`）
3. **records に昇格したら削除する**（記録番号をコメントとして残してもよい）
4. **月1回見直す**（陳腐化したアイデアは削除）

### 理由

- 古いアイデアが上に来るのを防ぐ — 最近のアイデアほど鮮度があり優先度が高い
- 日付があると「いつ思いついたか」が振り返りに役立つ
- records に昇格済みのものを残すと二重管理になる

### 却下した選択肢

| 案 | 却下理由 |
|---|---|
| カテゴリ別に整理する | 分類コストが高い。アイデア段階で分類するより records で整理すれば十分 |
| 優先度をつける | アイデアの価値は文脈依存で変わるため、追記時の優先度は意味をなさない |

### 影響

- ideas.md の既存フォーマットを変更する必要がある
- CLAUDE.md の出力ルール表に ideas.md の書き方を追記する

### docs 記載方針

- `packages/template/CLAUDE.md` の出力ルール表に ideas.md の書式（日付付き最上部追記）を追記

### 実装方針

1. `packages/template/in-progress/ideas.md` のサンプル内容を新フォーマットに更新
2. `packages/template/CLAUDE.md` に ideas.md の書き方を1行追記
