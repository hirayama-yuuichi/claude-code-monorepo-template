# 設計判断ログ

## 0017-010: V1・V2対応 — backlog記載漏れとサンプルコンテンツ設計

- 日付: 2026-05-10
- 状態: 採用
- ドキュメント: 未着手
- 実装: 完了

### 背景

[0017-000](./0017-000-実際のプロジェクトでの導入テスト.md) の観察 V1・V2 の対応記録。

**V1：records追加時のbacklog記載漏れ**

`records-add` スキルの SKILL.md ステップ6には「決定事項に実装タスクが含まれる場合、backlog.md に直接追記する」と既に明記されているため、仕様の欠如ではなく運用上の問題である。

根本原因の候補：
1. **認知的負荷**：スキル実行後にユーザーが backlog 追記を失念しやすい（強制されない）
2. **スキル出力の問題**：backlog 追記を促すメッセージが出力されない
3. **仕様の記述位置**：ステップ6が条件付き（「実装タスクが含まれる場合」）でユーザーが判断に迷う

**V2：サンプルコンテンツ設計の一括見直し**

テンプレートの初期サンプルコンテンツとユーザーの本物の記録が混在し、区別しにくい問題が発生した。

具体的な3点：
- サンプル records が `0001-000-xxx.md` から始まるため、本物の記録と連番が衝突する
- backlog を使い始めた時点でサンプルの記述が残っており邪魔
- サンプル系ファイルにファイル名での識別子がない

### 判断

**V1対策：条件を外し、毎回 backlog 追記を確認する**

`records-add` のステップ6の条件文「実装タスクが含まれる場合」を削除し、record 作成後に必ず「backlog に追加しますか？（不要なら skip）」と確認を取る形にする。

**V2対策：サンプルファイルに `sample-` プレフィックスを付ける**

テンプレート内のサンプルファイルはすべてファイル名を `sample-` で始める。連番は持たせず、本物の記録と名前空間を分ける。

| 対象ファイル | 変更後 |
|---|---|
| `in-progress/records/0001-000-xxx.md` | `in-progress/records/0000-000-sample.md` |
| `in-progress/backlog.md` のサンプル記述 | 削除（空の状態で配布） |
| `in-progress/ideas.md` のサンプル記述 | 削除（存在する場合） |

`0000` をサンプル専用の予約シリーズとする。本物の records は `0001-000-` から始まることが保証される。

### 理由

**V1**
- 条件付きのままでは「これは実装タスクか？」の判断をユーザーに委ねており、忘れる余地が生まれる
- 毎回確認することで漏れがなくなる。追加不要なケースは `skip` 一言で済む

**V2**
- `sample-` プレフィックスにより、ファイル一覧で一目でサンプルと判別できる
- 連番から切り離すことで、本物の `0001-000-` が常に先頭になる
- backlog・ideas.md を空にすることで、使い始めた瞬間にサンプルが邪魔にならない

### 却下した選択肢

| 案 | 却下理由 |
|---|---|
| V1: スキルが自動で backlog に追記 | record の内容を解析して「実装タスクか」を判定するのは難しく、誤追記のリスクがある |
| V1: CLAUDE.md に注意書きを追記 | 文書での啓発は読まれない。スキルのフロー内で促す方が確実 |
| V2: `_samples/` サブディレクトリに隔離 | ディレクトリが増えて構造が複雑になる。プレフィックスで十分識別できる |
| V2: サンプルファイルを一切含めない | 初めて使うユーザーがフォーマットを知るサンプルは有用。削除より改名が適切 |

### 影響

- `records-add` スキルのフローが変わる（ステップ6の条件削除・確認追加）
- テンプレート内のサンプルファイル名が変わる（`sample-` プレフィックス）
- backlog.md・ideas.md の初期内容が空になる

### docs 記載方針

- `packages/template/CLAUDE.md` にサンプルファイルの命名規則（`sample-` プレフィックス）を追記
