# 設計判断ログ

## 0019: records の枝番対応

- 日付: 2026-05-09
- 状態: 採用
- ドキュメント: 完了
- 実装: 完了

### 背景

records が増えるにつれ、ひとつの record から派生する検討事項（例：0017 の検証結果 V1・V2 が独立した record になる場合）が生まれる。現状の `XXXX-タイトル.md` という平坦な連番では、親 record との関係が失われ文脈が追いにくくなる。

### 判断

親 record の派生として記録する場合、以下の枝番形式を採用する：

```
{親番号}-{枝番}-{タイトル}.md
```

**採番ルール：**

| パターン | 例 | 意味 |
|---------|---|------|
| `0020-0-タイトル.md` | すべての record の基本形 | 新規 record は必ず `-0-` から始める |
| `0020-1-タイトル.md` | 根の派生 | `0020-0` の兄弟枝（セグメント数 = 深さ 1） |
| `0020-0-1-タイトル.md` | 枝の派生 | `0020-0` からさらに派生（セグメント数 = 深さ 2） |
| `0020-0-2-タイトル.md` | 枝の別の派生 | `0020-0` からの2番目の派生 |
| `0020-0-1-1-タイトル.md` | サブ枝の派生 | `0020-0-1` からさらに派生（セグメント数 = 深さ 3） |

**階層化のルール：** 「親パスの末尾に `-N-` を追加する」。セグメント数が深さを表す。

- **すべての record は `XXXX-0-タイトル.md` から始める**（独立テーマも含む）
- **`-0-` の意味：** 「この連番の根本記録（派生の有無を問わず本体）」であり、かつ派生枝の派生元親ノードでもある
- 枝番は 0 始まり、**最大 9 まで**（同一レベルの派生は10枝を上限とする）
- 派生が生まれたら親パスの末尾に `-1-`, `-2-` と追加する
- 10枝を超える場合は record の粒度を見直す

### 理由

- 親 record との関係がファイル名から読み取れる
- 平坦な連番を壊さずに派生記録を挿入できる
- ファイル名エンコードにより、記録本文を開かずに親子関係が把握できる。「0017 参照」という記録内参照だけでは、ファイル一覧を眺めたときに派生関係が見えにくいという欠点がある。この欠点は全 record に `-0-` を強制するコストより小さいと判断した

### 却下した選択肢

| 案 | 却下理由 |
|---|---|
| 親 record 内にセクション追記 | 1ファイルが肥大化し、critique/propose の対象として扱いにくい |
| `0017a`, `0017b` 形式 | 連番との区別が視覚的に分かりにくい |
| 完全な独立連番で管理 | 記録内参照（「0017 参照」等）でも親子関係は表現できるが、ファイル一覧上での文脈の見通しが失われる。この欠点と `-0-` 強制コストを比較し、ファイル名エンコードを選択した |

### 影響

- `records-add` スキルが枝番形式を採番できるよう修正が必要
- 既存 records は変更不要（遡及適用しない）

### docs 記載方針

- `packages/template/in-progress/records/` 配下のサンプル record が存在する場合、ファイル名規約に枝番形式を追記する
- CLAUDE.md の「出力ルール」表にある `XXXX-xxx.md` の記述を `XXXX-0-xxx.md` 形式に更新する（枝番形式が標準であることを反映）
- サンプル record の有無は実装時に確認する

### 実装方針

#### 1. `records-add` スキルの修正（`packages/skills/records-add/SKILL.md`）

**変更対象箇所：** `How It Works` セクション（現在の手順 2・3）および `Output` セクション

**新しい動作仕様：**

##### `--parent` なし（通常採番）

1. `in-progress/records/` の既存ファイルから連番部分（ファイル名先頭の4桁数字）を抽出し、最大値 + 1 を次の連番 `XXXX` とする
   - 抽出対象：`XXXX-0-タイトル.md` 形式のファイル（`_review.md`・`_proposal.md` サフィックスは除外する）
   - `XXXX-0-` の `XXXX` 部分のみをカウント対象とする
2. `in-progress/records/XXXX-0-<タイトル>.md` を作成する

##### `--parent <親パス>` あり（枝番採番）

`--parent` には任意の深さの親パスを指定できる（例：`0020-0`, `0020-0-1`）。

1. 親パス `<親パス>` に対応するファイル `<親パス>-*.md` が存在するか確認する
   - 存在しない場合：「親ファイル `<親パス>-*.md` が見つかりません。先に親 record を作成するか、パスを確認してください」とエラーを出力して終了する
2. `in-progress/records/<親パス>-N-*.md` の一覧を取得する（`_review.md`・`_proposal.md` サフィックスは除外する）
3. 取得した一覧から末尾の枝番 `N` の最大値を求め、`N + 1` を新しい枝番とする（一覧が空の場合は `1` から開始）
4. `in-progress/records/<親パス>-{N+1}-<タイトル>.md` を作成する

例：
- `--parent 0020-0` → `0020-0-1-タイトル.md`, `0020-0-2-タイトル.md`, ...
- `--parent 0020-0-1` → `0020-0-1-1-タイトル.md`, `0020-0-1-2-タイトル.md`, ...

**ファイル名採番から除外するパターン：**

- `*_review.md` サフィックスを持つファイル
- `*_proposal.md` サフィックスを持つファイル

これらは critique/propose スキルが生成する作業ファイルであり、連番・枝番の採番対象から除外することで誤カウントを防ぐ。

**`Output` セクションの更新：**

- `--parent` なし：`in-progress/records/XXXX-0-<タイトル>.md`
- `--parent <親パス>` あり：`in-progress/records/<親パス>-{N+1}-<タイトル>.md`
